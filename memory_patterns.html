4 Memory Patterns for AI Agents

Most agent token bills and "forgetful AI" complaints trace back to one root cause: no memory architecture. Battle-tested in production customer support systems.

The common mistake Stuffing every past message into the context window on every turn. Result: expensive, slow, and still forgetful, because past sessions are lost entirely. The fix is knowing which memory pattern fits which job.
1

Working Memory

What the agent is thinking about right now

The active message list inside one agent run. Grows every iteration. Dies when the run ends. Sent to the LLM on every turn.

Use when: within a single conversation turn. Automatic. You don't manage this.
Solves: active reasoning context.
2

Episodic Memory

What happened and when

Time-ordered event log. Scored by recency + keyword overlap. Fixed-size deque; oldest entries drop automatically. Survives across sessions.

Use when: agent needs to recall past conversations, decisions, or events.
await episodic.add( "User resolved refund for #1234", metadata={"topic": "refund"} )
3

Semantic Memory

What the agent knows, retrieved by meaning

Vector store. Each entry is embedded. Search returns entries with closest meaning, not just matching words. "car" matches "automobile".

Use when: agent needs facts or user preferences retrieved by concept.
results = await semantic.search( "vehicle policy", top_k=3 )
4

Procedural Memory

How to handle this type of task

Task to procedure lookup. Retrieved by Jaccard similarity on the task description. Think: playbooks, SOPs, workflow templates the agent recalls on demand.

Use when: agent needs to recall how to handle a category of request.
proc = await procedural.retrieve( "handle billing dispute" )
Exposing memory to the LLM as MCP tools
@app.tool() async def search_memory(query: str) -> str: episodes = await episodic.search(query, top_k=3) facts = await semantic.search(query, top_k=3) return format_results(episodes + facts)
@app.tool() async def get_procedure(task: str) -> str: proc = await procedural.retrieve(task) return proc.steps if proc else "No procedure found."
Working memory is automatic (the messages list). The other three become MCP tools the LLM calls during the ReAct loop to pull in context on demand.
Pattern Retrieves by Lifetime Token cost Best for
Working All (in context) One run High (everything sent) Active reasoning
Episodic Recency + keywords Persistent Low (top-K only) Past conversations
Semantic Meaning (cosine) Persistent Low (top-K only) Knowledge / facts
Procedural Task similarity Persistent Very low (one entry) SOPs / playbooks
The production pattern
Start run, recall relevant memories, agent works, compress session, store to episodic
